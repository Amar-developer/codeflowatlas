# Frontend experience

The current `frontend/` app is a Next.js foundation page styled with Tailwind CSS v4. It checks the FastAPI liveness and PostgreSQL readiness endpoints on each request, links to the API documentation, and labels future capabilities as planned. Its copy should describe the intended flow-learning experience for students and AI-assisted builders without suggesting that import, AI guidance, tracing, or load testing already works. Keep reusable page-wide defaults in `app/globals.css` and use utility classes for component styling.

The primary screens are project dashboard, GitHub/Bitbucket link import, analysis progress, API or feature selector, interactive flow graph and mind map, source viewer, and AI question panel. The graph is the main navigation surface: selecting a node or edge opens its source and explanation. The AI panel should cite file and line evidence, distinguish resolved from inferred steps, and work when there is no runtime. Later screens add a trace waterfall, request and query timing, issue explanation, optimization options, optional 100-user traffic and failure charts, and before/after history. The [visualization system](visualization-system.md) defines each view, evidence styling, and interactions. React Flow can render bounded graph slices; charts should expose units, sample sizes, and comparison conditions.

The interface should lead a learner from a repository link to one feature's visual code and data path, then let them select a step and ask what it does. A supported runtime can extend the same workspace with an observed trace, timings, errors, and a testable improvement idea; the deeper lab adds controlled load and fault charts. Large graphs need search, filters, focused slices, and a text step view. Empty states explain when a capability requires instrumentation or an isolated target. Error states name the failed step and preserve partial results when safe. Planned AI answers, measurements, or recommendations must not appear as if they have already been generated from live data.
