# Product scope

### Core product capabilities

1. Create projects and import a supported public GitHub or Bitbucket repository URL at a pinned Git revision, or a validated archive, into an isolated workspace. Private repository access requires a separate authorization design.
2. Analyze Python source without importing or executing it. Discover symbols, imports, resolvable calls, framework routes, and selected infrastructure usage.
3. Normalize findings into a versioned, language-neutral intermediate representation (IR), then persist an API catalog and code graph.
4. Let a learner select an API or feature and navigate an interactive flow graph and mind map of its route, handler, functions, dependencies, detectable database access, and response. Nodes and edges open file and line references, confidence, and source provenance.
5. Provide a source-grounded AI guide that explains each step in plain language, answers follow-up questions, cites inspected file and line evidence, and labels unresolved relationships. This source-only mode works without a running app or database.
6. Collect OpenTelemetry traces from a supported instrumented application, including endpoint duration, errors, and sanitized database query counts and timings; show a waterfall and link observed spans to source graph entities only when mapping evidence exists.
7. Explain observed issues with cited runtime evidence and offer testable optimization options, including query, indexing, cache, and concurrency strategies where relevant. State tradeoffs and allow a before/after rerun.
8. Offer optional repeatable, bounded traffic and edge-case scenarios against an allowlisted isolated target, including a configurable 100-concurrent-virtual-user learning scenario. Chart configured and achieved load, timings, errors, and resource metrics with units and sample counts.
9. Inject at least one controlled dependency failure or delay, compare behavior, and generate rule-based bottleneck findings with evidence.
10. Retain revisions and experiment runs so users can compare and reproduce results.
11. Offer an AI test bot that proposes reviewable API or browser journeys from discovered routes, schemas, and test fixtures; execute only the selected scenario against a disposable isolated target, report reproducible failures, and link each result to requests, traces, and code.
12. Build a synthetic runtime dataset for supported targets from verified source models, migrations, or fixtures. The AI may propose missing schema or seed details, but these remain hypotheses until the target starts and passes validation. Never read, copy, or connect to the imported application's original or production data.
13. Add optional learning exercises and flow diffs so a student can predict behavior and compare a code path across revisions. These follow the first complete source walkthrough and are not prerequisites for it.
14. Extend source analysis across supported frontend and backend frameworks. The first full-stack path links a React/Next.js page action or data load to a FastAPI endpoint through a resolvable HTTP request; later adapters can cover Express, NestJS, Flask, and Django with separate capability gates and fixtures.
15. Offer linked visualization levels: a source-grounded repository overview, a feature or API flow, and a function-level call path. Let users move between levels while keeping the selected revision, source links, confidence, and unresolved areas visible. An architecture view is a map of detected relationships, not a complete system design claim.
16. Accept natural-language questions about the selected revision or graph step. Return a concise answer, relevant code excerpts with file and line references, and a focused visualization when the available evidence supports one. Offer live query suggestions based on discovered entities, endpoints, and example questions; suggestions must stay in the current project and be editable before submission.
17. Let users export a selected diagram for documentation and collaboration, initially as SVG or PNG with a readable title, revision identity, legend, and visible uncertainty. Export only what the user is authorized to view, and provide the same essential path as text.
18. Offer an optional, user-triggered prompt draft for an LLM based on the selected question and cited, bounded evidence. Show and let the user edit exactly what will be copied or sent; exclude secrets and unrelated repository content. The prompt is an aid to further analysis, not proof of a code path or runtime behavior.

### Explicit boundaries

The first implementation proves the flow on a FastAPI fixture before accepting external repository URLs. The intended complete workflow supports safe import from public GitHub and Bitbucket links. A later full-stack fixture links a supported React/Next.js frontend action to FastAPI; Express is the next backend family to evaluate, with NestJS, Flask, and Django added only after their own fixture and UI evidence gates. The support roadmap distinguishes framework detection, route or page cataloguing, source flow, observed flow, and test-lab capability. Dynamic HTTP URLs or unknown proxy routes remain unresolved rather than guessed. Importing a repository permits source analysis; it does not imply that arbitrary applications can be started or instrumented. Runtime timing, the AI test bot, and the 100-user lab require a supported approved isolated target, disposable dependencies, synthetic data, and resource, duration, and destination limits. Local testing requires a user-installed runner; a web page cannot silently run containers on the user's machine. Hosted execution is a later operating model. If setup, schema, or instrumentation cannot be validated, show the source-only result and a concrete unsupported reason. Java/Spring and Go frameworks remain later candidates, not promised support. Production deployment, large-scale distributed processing, automatic architecture classification, and broad fault injection are extensions. Imported applications are never run on the host during analysis. CodeFlowAtlas does not autonomously modify a user's repository, access original databases or credentials, expose raw values or secrets, load-test arbitrary live sites, or claim that an LLM can prove runtime behavior. See the [framework support roadmap](../analysis/framework-support-roadmap.md).
